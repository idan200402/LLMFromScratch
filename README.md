# LLM From Scratch

This project is a learning notebook that builds a small character-level language model from the ground up in PyTorch. The main file is `pipeLine.ipynb`, which gradually moves from basic text preprocessing to a Transformer-style decoder that can generate Shakespeare-like text.

The code follows the same general path as a small GPT implementation:

1. Turn raw text into integer tokens.
2. Create input/target training batches.
3. Train a simple next-character model.
4. Add self-attention so each token can use previous context.
5. Add multi-head attention and feed-forward layers.
6. Scale the model with residual connections, layer normalization, dropout, and stacked blocks.

## Files

- `pipeLine.ipynb` - the main notebook, containing the full step-by-step implementation.
- `input.txt` - the training corpus. The notebook reads this file and learns from it.
- `generated_text.txt` - sample text generated by the trained model.
- `bigram_model.pth` - saved model checkpoint.
- `gpu_test.py` - small helper script for checking GPU availability.

## What the Notebook Does

### 1. Load the Dataset

The notebook starts by reading `input.txt`:

```python
with open('input.txt', 'r', encoding='utf-8') as file:
    data = file.read()
```

The dataset is treated as one long string. The model learns to predict the next character from previous characters.

### 2. Build the Vocabulary

The notebook collects all unique characters in the text:

```python
chars = sorted(list(set(data)))
```

For the current dataset, the vocabulary size is 65 characters. Each character gets an integer ID:

- `char_to_int`: maps a character to a token ID.
- `int_to_char`: maps a token ID back to a character.
- `encode`: converts text into a list of token IDs.
- `decode`: converts token IDs back into text.

This is character-level tokenization. There are no words or subwords here, only individual characters.

### 3. Convert Text to Tensors

The encoded text is converted into a PyTorch tensor:

```python
data = torch.tensor(encode(text), dtype=torch.long, device=device)
```


### 4. Split Train and Validation Data

The data is split into:

- 90% training data
- 10% validation data

  
### 5. Create Input and Target Sequences

The model is trained with next-token prediction.

If the input is:

```text
First Citize
```

the target is the same text shifted one character forward:

```text
irst Citizen
```


The important shape is:

```text
B x T
```

where:

- `B` is batch size.
- `T` is time/context length, also called `block_size`.

The `get_batch(split)` function samples random chunks from the training or validation data and returns:

```python
x, y
```

where:

- `x` is the input tokens.
- `y` is the target next tokens.

## Model Progression

The notebook improves the model gradually. Each version adds one important idea.

## Model 1: Basic Bigram Language Model

The first model is a simple bigram model:

```python
self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)
```

For every input character, the model directly predicts logits for the next character.

Input shape:

```text
B x T
```

Output logits shape:

```text
B x T x vocab_size
```

This model has no real memory. It only knows what character it is currently looking at. It cannot understand longer context.

Example limitation:

- It can learn that `q` is often followed by `u`.
- It cannot use a long phrase or sentence structure to make better predictions.

Training uses cross-entropy loss:

```python
loss = F.cross_entropy(logits, targets)
```

Generation works by:

1. Taking the last predicted token.
2. Applying softmax to get probabilities.
3. Sampling the next token with `torch.multinomial`.
4. Appending the sampled token to the sequence.

## Attention Experiments

Before adding attention to the model, the notebook demonstrates how tokens can communicate with previous tokens.

### Manual Averaging

The first attention-like experiment manually loops over each time step:

```python
xprev = x[b, :t + 1]
xbow[b, t] = torch.mean(xprev, dim=0)
```

For each token, it averages all previous token vectors, including itself.

This gives each position information about the past, but it is slow and uses explicit Python loops.

### Matrix Multiplication Version

The notebook then replaces the loop with a lower-triangular matrix:

```python
wei = torch.tril(torch.ones(T, T))
wei = wei / torch.sum(wei, dim=1, keepdim=True)
xbow = wei @ x
```

The lower-triangular matrix prevents future tokens from being used. This is called a causal mask.

This is the same idea as before, but vectorized and much faster.

### Softmax Version

The notebook then introduces the usual attention pattern:

```python
wei = wei.masked_fill(tril == 0, float('-inf'))
wei = F.softmax(wei, dim=-1)
```

Instead of manually normalizing rows, softmax turns attention scores into probabilities. Future positions are set to `-inf`, so after softmax they receive probability 0.

## Model 2: Bigram Model with One Self-Attention Head

The next model adds token embeddings, position embeddings, and a single attention head.

Important pieces:

```python
self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
self.position_embedding_table = nn.Embedding(block_size, n_embd)
self.sa_head = Head(n_embd)
self.lm_head = nn.Linear(n_embd, vocab_size)
```

This is a major improvement over the first bigram model.

The model now knows:

- what character/token it is looking at
- where that token appears in the context window
- what previous tokens are relevant

The attention head uses three learned projections:

- `key`: what each token contains
- `query`: what each token is looking for
- `value`: what information each token contributes

The attention weights are computed with:

```python
wei = q @ k.transpose(-2, -1) * (k.shape[-1] ** -0.5)
```

The scaling factor keeps the dot products from becoming too large, which helps softmax stay stable.

The causal mask still prevents tokens from looking into the future:

```python
wei = wei.masked_fill(self.tril[:T, :T] == 0, float('-inf'))
```

## Model 3: Multi-Head Attention plus Feed-Forward Layer

The next version adds multiple attention heads:

```python
self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)])
```

Each head can learn a different relationship between tokens. One head might focus on nearby characters, another on punctuation, another on speaker-name patterns, and so on.

The outputs of all heads are concatenated:

```python
torch.cat([h(x) for h in self.heads], dim=-1)
```

Then the model adds a feed-forward network:

```python
self.ffwd = FeedForward(n_embd)
```

Attention lets tokens exchange information. The feed-forward layer lets the model process that information independently at each position.

This version is stronger because it has:

- several attention heads instead of one
- more representation power after attention
- token embeddings
- positional embeddings
- next-token prediction head

## Model 4: Scaled Transformer-Style Decoder

The final notebook model scales the architecture closer to a real GPT-style decoder.

Hyperparameters used in the notebook:

```python
batch_size = 32
block_size = 128
learning_rate = 3e-4
n_layer = 6
n_heads = 6
n_embd = 384
dropout = 0.2
```

The model adds several important improvements.

### Stacked Transformer Blocks

Instead of one attention layer, the model stacks multiple blocks:

```python
self.blocks = nn.Sequential(
    *[Block(n_embd, num_heads=n_heads) for _ in range(n_layer)]
)
```

Each block contains:

1. Layer normalization
2. Multi-head self-attention
3. Residual connection
4. Layer normalization
5. Feed-forward network
6. Residual connection

### Residual Connections

Inside each block:

```python
x = x + self.sa(self.ln1(x))
x = x + self.ffwd(self.ln2(x))
```

Residual connections let the model keep the original representation while adding learned updates. This makes deeper models easier to train.

### Layer Normalization

Layer normalization stabilizes training:

```python
self.ln1 = nn.LayerNorm(n_embd)
self.ln2 = nn.LayerNorm(n_embd)
self.ln_f = nn.LayerNorm(n_embd)
```

The notebook uses a pre-layer-normalization style: normalize first, then apply attention or feed-forward.

### Dropout

Dropout is added for regularization:

```python
self.dropout = nn.Dropout(dropout)
```

This helps reduce overfitting by randomly dropping parts of the representation during training.

### Final Language Model Head

After all Transformer blocks, the model projects the final hidden representation back to vocabulary logits:

```python
self.lm_head = nn.Linear(n_embd, vocab_size)
```

The result is still next-character prediction, but the model now uses a much richer context representation.

## Why Each Model Is Better Than the Previous One

| Stage | Main Idea | Improvement |
| --- | --- | --- |
| Basic bigram | Current character predicts next character | Simple baseline, but no context |
| Single attention head | Learned key/query/value attention | Tokens learn what past tokens matter |
| Multi-head attention | Several attention heads in parallel | Learns different relationships at once |
| Feed-forward layer | Per-token nonlinear processing | More representation power |
| Transformer blocks | Stack attention and feed-forward layers | Deeper reasoning over context |
| Residual connections | Add updates instead of replacing state | More stable deep training |
| Layer normalization | Normalize activations | Better optimization |
| Dropout | Randomly drop activations during training | Better generalization |

## Training Loop

The training loop follows the standard PyTorch pattern:

```python
xb, yb = get_batch('train')
logits, loss = m(xb, yb)
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
```

The final model also checks validation loss:

```python
xb_val, yb_val = get_batch('val')
_, val_loss = m(xb_val, yb_val)
```

Validation loss is useful because it shows whether the model is learning general patterns or only memorizing the training data.

## Text Generation

Generation starts from a small seed tensor:

```python
idx = torch.zeros((1, 1), dtype=torch.long, device=device)
```

Then the model repeatedly predicts one new character at a time:

```python
print(decode(m.generate(idx, max_new_tokens=1000)[0].tolist()))
```

For long generation, the model only keeps the last `block_size` tokens:

```python
idx_cond = idx[:, -block_size:]
```

This is because the position embedding table and attention mask are built for a fixed context window.




## How to Run

Open `pipeLine.ipynb` and run the cells from top to bottom.

Recommended environment:

- Python 3
- PyTorch
- CUDA-capable GPU if available

The notebook will still run on CPU, but training the larger model will be much slower.

## Notes

This exploration is based on Andrej Karpathy's educational `nanoGPT` / "Let's build GPT from scratch" work, adapted here as a step-by-step learning notebook.

The class name `BigramLanguageModel` is reused across several versions. In the later sections, the model is no longer truly just a bigram model; it becomes a Transformer-style decoder. Keeping the same name is fine for a learning notebook, but in a cleaned-up Python module, each model version should probably have a more specific class name.

The final generated text has Shakespeare-like formatting and structure because the model is trained on character sequences from the input corpus. It learns character patterns, words, punctuation, line breaks, and speaker-name style only from next-character prediction.
